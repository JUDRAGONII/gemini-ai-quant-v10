## 第一章：驗收測試總覽

### 1.1 驗收測試目的與範疇

使用者驗收測試（User Acceptance Testing，UAT）是軟體開發生命週期中的關鍵階段，由系統的最終用戶或業務代表執行，驗證系統是否真正滿足業務需求並能夠投入實際使用。對於 AI 投資分析儀 V10.0，UAT 階段的核心目標是確認系統能夠支援兩位專業投資人的日常投資分析工作流程，確保系統功能與效能符合預期，且 AI 分析結果具有可信度。

本驗收測試計畫的範疇涵蓋所有功能模組的端對端驗證，包含：行情數據查詢與分析、宏觀經濟數據追蹤、籌碼分析功能、AI 投資評分與報告生成、投資組合管理、系統設定與偏好配置。測試情境設計貼近真實使用情境，由用戶代表親自執行，確保測試結果反映實際使用體驗。

### 1.2 驗收測試策略

驗收測試採用分階段、分模組的策略進行，確保測試的完整性與效率。

第一階段為功能驗證階段，驗證各功能模組是否符合規格定義，確認功能完整性與正確性。此階段由測試團隊引導用戶執行，用戶按照測試案例操作並確認結果。

第二階段為情境演練階段，模擬用戶的典型工作日流程，驗證系統在實際使用情境下的表現。此階段由用戶自主執行，測試團隊記錄用戶回饋與發現的問題。

第三階段為效能驗證階段，在接近生產環境的條件下執行效能測試，驗證系統響應時間與穩定性。此階段由測試團隊執行，邀請用戶觀察測試結果。

第四階段為最終驗收階段，確認所有發現的問題已修復，用戶對系統品質有信心，正式簽核驗收通過。

### 1.3 參與角色與職責

| 角色 | 主要職責 |
|------|----------|
| 用戶代表 | 執行測試案例、提供業務觀點、確認功能符合需求 |
| 測試主管 | 規劃測試計畫、協調測試執行、追蹤問題修復、產生測試報告 |
| 測試工程師 | 準備測試環境、支援測試執行、記錄測試結果 |
| 開發團隊 | 修復測試發現的問題、回答技術問題 |
| 專案經理 | 資源協調、進度管控、風險管理 |

## 第二章：測試環境與資料

### 2.1 測試環境配置

驗收測試環境應盡可能接近正式生產環境，以確保測試結果的可信度。

| 元件 | 環境配置 |
|------|----------|
| 執行環境 | QNAP TS-h973AX-32G 本機部署 |
| Docker Compose | 與正式環境相同版本配置 |
| 資料庫 | PostgreSQL 15，資料為正式數據副本 |
| 測試資料 | 經脫敏處理的正式數據，包含 2 年歷史行情 |
| 測試用戶 | 2 個測試用戶帳號（測試環境專用） |
| 測試期限 | 測試開始後 10 個工作天 |

### 2.2 測試用戶角色

為完整測試系統功能，UAT 階段設定以下測試用戶角色：

| 用戶角色 | 使用情境 | 測試重點 |
|----------|----------|----------|
| 主動投資型用戶 | 頻繁交易決策、短期投資分析 | 行情查詢、技術分析、籌碼分析、AI 評分 |
| 研究型用戶 | 長期投資研究、宏觀分析 | 宏觀指標、估值分析、機構持倉比較 |

### 2.3 測試資料集

測試資料集包含以下類別的代表性樣本：

台股測試樣本：2330 台積電（大型權值股、科技股代表）、0050 元大台灣 50（ETF 代表）、2317 鴻海（電子股代表）、2886 兆豐金（金融股代表）、3501 聯發科（IC 設計股代表）。

美股測試樣本：AAPL 蘋果（科技股代表）、MSFT 微軟（軟體股代表）、GOOGL Alphabet（網路股代表）、JPM 摩根大通（金融股代表）、TSLA 特斯拉（成長股代表）。

宏觀數據測試樣本：美國 CPI、聯邦基金利率、非農就業人數、台灣 GDP、外匯匯率。

## 第四章：測試執行程序

### 4.1 測試準備

測試執行前的準備工作確保測試順利進行：

環境準備檢查清單：
- [ ] 測試環境已部署並驗證正常運行
- [ ] 測試資料已載入並完成驗證
- [ ] 測試用戶帳號已建立
- [ ] 測試文件已分發給參與人員

人員準備檢查清單：
- [ ] 用戶代表已了解測試案例內容
- [ ] 測試團隊已完成測試環境操作培訓
- [ ] 緊急聯絡人清單已分發

### 4.2 測試執行紀錄

每個測試案例需詳細記錄以下資訊：

| 欄位 | 填寫說明 |
|------|----------|
| 測試日期 | 執行測試的日期 |
| 測試人員 | 執行測試的用戶代表姓名 |
| 測試環境 | 使用的測試環境識別資訊 |
| 測試結果 | 通過 / 失敗 / 阻擋 |
| 實際結果描述 | 詳細描述實際觀察到的結果 |
| 問題描述 | 若測試失敗，描述問題現象 |
| 截圖 | 異常情況的截圖證據 |
| 嚴重程度 | 阻擋（Blocker）/ 嚴重（Critical）/ 一般（Major）/ 輕微（Minor）|

### 4.3 問題分級與處理

| 嚴重程度 | 定義 | 處理時效 |
|----------|------|----------|
| 阻擋（Blocker） | 測試無法繼續進行，影響核心功能 | 24 小時內修復 |
| 嚴重（Critical） | 主要功能失效或資料錯誤 | 48 小時內修復 |
| 一般（Major） | 功能異常但不影響主要流程 | 5 個工作天內修復 |
| 輕微（Minor） | UI 顯示問題或建議性改善 | 可排入後續版本 |

## 第五章：驗收標準與簽核

### 5.1 驗收通過標準

UAT 驗收通過需滿足以下條件：
