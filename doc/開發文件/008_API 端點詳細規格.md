## 第一章：API 總則

### 1.1 API 設計原則

本 API 遵循 RESTful 設計原則，提供標準化的 HTTP 介面。所有端點採用 JSON 格式進行資料交換，並遵循以下設計規範：資源導向的 URL 設計、標準 HTTP 方法（GET、POST、PUT、DELETE）、一致的請求與響應格式、HATEOAS 超連結支援、版本化 URL（/api/v1/）、標準化的錯誤碼定義。

API 安全性方面，所有端點需透過 API Key 或 JWT Token 進行認證。支援 HTTPS SSL/TLS 加密傳輸。實施速率限制以確保服務穩定性。詳細的認證機制請參考《RESTful API 設計規範》文件。

### 1.2 基礎 URL 與版本

| 環境 | 基礎 URL | 端口 |
|------|----------|------|
| 生產環境 | https://your-nas-domain.com/api/v1 | 443 |
| 測試環境 | https://your-nas-domain.com:8000/api/v1 | 8000 |
| 本地開發 | http://localhost:8000/api/v1 | 8000 |

### 1.3 請求與響應規範

**請求 Header 規範**：

| Header | 必填 | 說明 |
|--------|------|------|
| Authorization | 是 | Bearer {API_KEY} 或 Bearer {JWT_TOKEN} |
| Content-Type | POST/PUT | application/json |
| Accept | 建議 | application/json |
| X-Request-ID | 建議 | 請求追蹤標識 |

**成功響應格式**：

```json
{
    "status": "success",
    "data": { ... },
    "meta": {
        "page": 1,
        "per_page": 20,
        "total": 100,
        "has_more": true
    },
    "timestamp": "2026-01-27T10:30:00Z"
}
```

**錯誤響應格式**：

```json
{
    "status": "error",
    "error": {
        "code": "40001",
        "message": "Invalid parameter: stock_code",
        "details": { "stock_code": "Stock code not found" }
    },
    "timestamp": "2026-01-27T10:30:00Z"
}
```

## 第二章：身份認證 API

### 2.1 使用者登入

**端點**：`POST /api/v1/auth/login`

**請求參數**：

| 參數 | 類型 | 必填 | 說明 |
|------|------|------|------|
| email | string | 是 | 註冊電子郵件 |
| password | string | 是 | 帳戶密碼 |

**請求範例**：

```json
{
    "email": "user@example.com",
    "password": "secure_password"
}
```

**響應資料**：

```json
{
    "status": "success",
    "data": {
        "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
        "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
        "token_type": "Bearer",
        "expires_in": 3600,
        "user": {
            "id": "uuid-uuid-uuid",
            "email": "user@example.com",
            "name": "使用者姓名",
            "role": "user"
        }
    },
    "timestamp": "2026-01-27T10:30:00Z"
}
```

**HTTP 狀態碼**：
- 200：登入成功
- 401：帳號或密碼錯誤
- 423：帳號已鎖定

### 2.2 刷新存取權杖

**端點**：`POST /api/v1/auth/refresh`

**請求參數**：

| 參數 | 類型 | 必填 | 說明 |
|------|------|------|------|
| refresh_token | string | 是 | 登入時取得的刷新權杖 |

**響應資料**：

```json
{
    "status": "success",
    "data": {
        "access_token": "new_access_token...",
        "token_type": "Bearer",
        "expires_in": 3600
    },
    "timestamp": "2026-01-27T10:30:00Z"
}
```

### 2.3 取得当前用户資訊

**端點**：`GET /api/v1/auth/me`

**響應資料**：

## 第八章：RPC 函數參考

### 8.1 函數清單

| 函數名稱 | 說明 | 參數 |
|----------|------|------|
| `get_evolution_fitness` | 計算目前基因組的適應度 | `{"user_id": "uuid"}` |
| `match_reports` | 餘弦相似度向量檢索 | `{"query_embedding": [...], "match_threshold": 0.5, "match_count": 5}` |
| `get_backfill_progress` | 獲取數據回補百分比進度 | 無 |
| `calculate_portfolio_return` | 計算投資組合報酬 | `{"portfolio_id": "uuid", "start_date": "...", "end_date": "..."}` |
| `get_stock_similar` | 取得相似股票 | `{"stock_code": "2330", "method": "fundamental", "limit": 5}` |

### 8.2 match_reports 函數

**呼叫方式**：

```sql
SELECT * FROM match_reports(
    query_embedding => '[0.12, 0.34, 0.56, ...]',
    match_threshold => 0.7,
    match_count => 10
);
```
