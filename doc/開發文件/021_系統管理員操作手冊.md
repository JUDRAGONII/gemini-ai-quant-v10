## 第一章：管理員總覽

### 1.1 手冊目的與對象

本手冊為 AI 投資分析儀 V10.0 系統管理員提供完整的操作指南，涵蓋系統配置、使用者管理、效能調校與故障排除等進階操作。閱讀本手冊前，管理員應具備基本的資訊技術背景，熟悉 Linux 指令操作與 Docker 容器基礎概念。

本手冊適用於以下人員：系統管理員（負責日常系統維護）、資料庫管理員（負責資料庫效能與安全）、維運工程師（負責監控與告警處理）。不同角色的管理員可依據職責選擇性閱讀相關章節。

### 1.2 系統架構複習

AI 投資分析儀 V10.0 採用容器化部署架構，主要元件包括：

| 元件 | 容器名稱 | 監聽端口 | 功能說明 |
|------|----------|----------|----------|
| API 服務 | api | 8000 | 提供 RESTful API |
| PostgreSQL | db | 5432 | 主資料庫 |
| Redis | redis | 6379 | 快取服務 |
| Prefect Worker | worker | - | 工作流執行 |
| Nginx | nginx-proxy | 80/443 | 反向代理 |
| Prometheus | prometheus | 9090 | 監控指標收集 |
| Grafana | grafana | 3000 | 監控儀表板 |

所有容器透過 Docker Compose 管理，配置文件位於 `/opt/ai-investor/docker-compose.yml`。

## 第二章：系統配置管理

### 2.1 環境變數配置

系統配置主要透過環境變數管理。環境變數檔案位於 `/opt/ai-investor/.env`。以下為主要配置項目說明：

```bash
# ========== 基礎配置 ==========
COMPOSE_PROJECT_NAME=ai_investor
APP_ENV=production

# ========== API 服務配置 ==========
API_HOST=0.0.0.0
API_PORT=8000
API_DEBUG=false

# ========== 資料庫配置 ==========
POSTGRES_USER=postgres
POSTGRES_PASSWORD=your_secure_password
POSTGRES_DB=ai_investor
DATABASE_URL=postgresql://postgres:your_secure_password@db:5432/ai_investor

# ========== Redis 配置 ==========
REDIS_URL=redis://redis:6379/0

# ========== AI 模型配置 ==========
GEMINI_API_KEY=your_gemini_api_key
GROQ_API_KEY=your_groq_api_key

# ========== 數據 API 配置 ==========
FINNHUB_API_KEY=your_finnhub_api_key
FUGLE_API_KEY=your_fugle_api_key
FMP_API_KEY=your_fmp_api_key
TIINGO_API_KEY=your_tiingo_api_key

# ========== 安全配置 ==========
JWT_SECRET_KEY=your_jwt_secret_key_min_32_chars
ENCRYPTION_KEY=your_encryption_key_32_chars

# ========== 監控配置 ==========
PROMETHEUS_RETENTION=15d
GRAFANA_ADMIN_PASSWORD=your_grafana_password
```

修改環境變數後，需重啟相關服務使變更生效：

```bash
# 重新載入配置並重啟服務
cd /opt/ai-investor
docker-compose down
docker-compose up -d
```

### 2.2 Nginx 配置

Nginx 作為系統的反向代理，負責 SSL 終止與請求分發。配置文件位於 `/opt/ai-investor/nginx/conf.d/default.conf`。

主要配置區塊：

```nginx
# upstream 定義後端服務
upstream api_server {
    server api:8000;
    keepalive 32;
}

upstream grafana_server {
    server grafana:3000;
}

# HTTP 重定向至 HTTPS
server {
    listen 80;
    server_name _;
    return 301 https://$host$request_uri;
}

# HTTPS 伺服器配置
server {
    listen 443 ssl http2;
    server_name your-nas-ip-or-domain;
    
    # SSL 憑證配置（使用 Let's Encrypt）
    ssl_certificate /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    
    # API 路由
    location /api/ {
        proxy_pass http://api_server;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # 速率限制
        limit_req zone=api_limit burst=20 nodelay;
    }
    
    # Grafana 路由
    location /grafana/ {
        proxy_pass http://grafana_server;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    
    # 健康檢查端點
    location /health {
        return 200 'OK';
        add_header Content-Type text/plain;
    }
}
```

Nginx 配置變更後，重新載入配置：

```bash
docker exec nginx-proxy nginx -s reload
```

### 2.3 Docker Compose 配置

Docker Compose 配置定義所有服務的執行參數。关键配置說明：

```yaml
version: '3.8'

services:
  api:
    build: ./app
    restart: unless-stopped
    environment:
      - DATABASE_URL=${DATABASE_URL}
      - REDIS_URL=${REDIS_URL}
    volumes:
      - app_data:/app/data
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 10s
      retries: 3
    deploy:
      resources:
        limits:
          cpus: '2'
          memory: 2G
        reservations:
          cpus: '1'
          memory: 1G

  db:
    image: postgres:15-alpine
    restart: unless-stopped
    environment:
      - POSTGRES_USER=${POSTGRES_USER}
      - POSTGRES_PASSWORD=${POSTGRES_PASSWORD}
      - POSTGRES_DB=${POSTGRES_DB}
    volumes:
      - pgdata:/var/lib/postgresql/data
      - pg_backup:/backup
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    restart: unless-stopped
    command: redis-server --maxmemory 512mb --maxmemory-policy allkeys-lru
    volumes:
      - redis_data:/data

  worker:
    build: ./app
    restart: unless-stopped
    command: prefect worker start ...
    environment:
      - PREFECT_API_URL=${PREFECT_API_URL}
    volumes:
      - prefect_data:/root/.prefect

volumes:
  pgdata:
    driver: local
  redis_data:
    driver: local
  app_data:
    driver: local
  prefect_data:
    driver: local
  pg_backup:
    driver: local
```

## 第三章：使用者管理

### 3.1 使用者帳號管理

系統使用者管理透過 API 或直接資料庫操作進行。建議使用 API 管理帳號，確保操作記錄完整性。

**建立新使用者**：

```bash
curl -X POST "http://localhost:8000/api/v1/admin/users" \
  -H "Authorization: Bearer admin_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "name": "使用者姓名",
    "role": "analyst",
    "password": "initial_password"
  }'
```

**使用者角色說明**：

| 角色 | 權限說明 |
|------|----------|
| admin | 完全系統管理權限 |
| analyst | 數據查詢與 AI 分析權限，無系統配置權限 |
| user | 基本數據查詢權限 |

**重設使用者密碼**：

```bash
curl -X POST "http://localhost:8000/api/v1/admin/users/{user_id}/reset-password" \
  -H "Authorization: Bearer admin_api_key"
```

### 3.2 API Key 管理

API Key 用於程式化存取 API。管理員可透過以下方式管理：

**建立 API Key**：

```bash
curl -X POST "http://localhost:8000/api/v1/admin/api-keys" \
  -H "Authorization: Bearer admin_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "開發環境 Key",
    "permissions": ["read"],
    "rate_limit": 100,
    "expires_at": "2026-12-31T23:59:59Z"
  }'
```

**撤銷 API Key**：

```bash
curl -X DELETE "http://localhost:8000/api/v1/admin/api-keys/{key_id}" \
  -H "Authorization: Bearer admin_api_key"
```

**檢視 API Key 使用量**：

```bash
curl -X GET "http://localhost:8000/api/v1/admin/api-keys/usage" \
  -H "Authorization: Bearer admin_api_key"
```

### 3.3 權限審核

系統記錄所有敏感操作，支援審計追蹤。管理員可查看審計日誌：

```bash
curl -X GET "http://localhost:8000/api/v1/admin/audit-logs?start_date=2026-01-01" \
  -H "Authorization: Bearer admin_api_key"
```

審計日誌包含：操作時間、操作者、操作類型、目標資源、操作結果、客戶端 IP。

## 第四章：效能監控與調校

### 4.1 監控儀表板存取

Grafana 監控儀表板提供系統健康狀態的視覺化呈現。存取方式：瀏覽器開啟 `https://your-nas-ip/grafana`，使用管理員帳號登入。

預設儀表板包含：系統總覽（CPU、記憶體、磁碟、網路）、API 效能儀表板（請求率、回應時間、錯誤率）、資料庫效能儀表板（連線數、查詢延遲、緩衝池命中率）、容器狀態儀表板（所有容器健康狀態）。

### 4.2 常用監控指令

**檢查所有容器狀態**：

```bash
cd /opt/ai-investor
docker-compose ps
```

**檢查容器資源使用**：

```bash
docker stats --no-stream
```

**檢查 API 服務日誌**：

```bash
docker logs ai_investor-api-1 --tail 100 -f
```

**檢查資料庫連線數**：

```bash
docker exec -it ai_investor-db-1 psql -U postgres -c "SELECT count(*) FROM pg_stat_activity;"
```

### 4.3 效能調校建議

**資料庫效能調校**：

當資料庫查詢效能下降時，考慮以下調校措施：

```sql
-- 檢視慢查詢
SELECT pid, now() - pg_stat_activity.query_start AS duration, query
FROM pg_stat_activity
WHERE (now() - pg_stat_activity.query_start) > interval '5 seconds'
AND state != 'idle'
ORDER BY duration DESC;

-- 分析資料表膨脹
SELECT schemaname, relname, n_live_tup, n_dead_tup, last_vacuum, last_autovacuum
FROM pg_stat_user_tables
ORDER BY n_dead_tup DESC;
```

**容器資源調整**：

若發現容器資源不足，編輯 docker-compose.yml 調整資源限制：

```yaml
services:
  api:
    deploy:
      resources:
        limits:
          cpus: '4'      # 增加 CPU 限制
          memory: 4G     # 增加記憶體限制
```

調整後執行 `docker-compose up -d` 重新部署。

## 第五章：故障排除

### 5.1 常見問題診斷

**服務無法啟動**：

```bash
# 1. 檢查容器日誌
docker-compose logs api

# 2. 檢查端口衝突
netstat -tlnp | grep 8000

# 3. 檢查環境變數
docker-compose config
```

**資料庫連線失敗**：

```bash
# 1. 檢查資料庫容器狀態
docker-compose ps db

# 2. 測試資料庫連線
docker exec -it ai_investor-db-1 pg_isready -U postgres

# 3. 檢查連線字串
docker exec -it ai_investor-api-1 printenv DATABASE_URL
```

**API 回應緩慢**：

```bash
# 1. 檢查系統資源
htop
df -h

# 2. 檢查資料庫效能
docker exec -it ai_investor-db-1 psql -U postgres -c "SELECT * FROM pg_stat_activity;"

# 3. 檢查 Redis 狀態
docker exec -it ai_investor-redis-1 redis-cli info
```

### 5.2 日誌分析

**收集所有服務日誌**：

```bash
mkdir -p /tmp/logs
for service in api db redis worker nginx; do
    docker-compose logs $service --since 1h > /tmp/logs/${service}.log
done
```

**搜尋錯誤日誌**：

```bash
# 搜尋所有服務中的錯誤
grep -r "ERROR" /tmp/logs/*.log

# 搜尋特定時間範圍的日誌
docker logs ai_investor-api-1 --since "2026-01-27 10:00" | grep "ERROR"
```

### 5.3 緊急復原程序

**服務完全停止時的復原步驟**：

```bash
cd /opt/ai-investor

# 1. 停止所有服務
docker-compose down

# 2. 清理異常狀態
docker system prune -f

# 3. 重新啟動所有服務
docker-compose up -d

# 4. 確認所有服務健康
docker-compose ps
docker-compose exec api curl -f http://localhost:8000/health
```

**資料庫損壞時的復原**：

```bash
# 1. 停止相關服務
docker-compose stop api worker

# 2. 從備份恢復
docker exec -it ai_investor-db-1 pg_restore -U postgres -d ai_investor /backup/latest.dump

# 3. 重啟服務
docker-compose start api worker
```

## 第六章：維護作業

### 6.1 例行維護排程

| 維護週期 | 維護項目 | 執行指令 |
|----------|----------|----------|
| 每日 | 檢查備份狀態 | `ls -la /backup_data/pg_dump/` |
| 每日 | 檢查監控告警 | 登入 Grafana 查看 |
| 每日 | 檢查日誌錯誤 | `docker-compose logs --since 24h | grep ERROR` |
| 每週 | 清理過期日誌 | `find /var/log -mtime +7 -delete` |
| 每週 | VACUUM 資料庫 | `docker exec ai_investor-db-1 psql -U postgres -c "VACUUM ANALYZE;"` |
| 每月 | 測試備份恢復 | 參考災難復原計畫 |
| 每季 | 軟體版本更新 | `docker-compose pull && docker-compose up -d` |

### 6.2 資料庫維護

**資料庫重組（VACUUM）**：

```bash
# 標準 VACUUM（不鎖定表格）
docker exec ai_investor-db-1 psql -U postgres -d ai_investor -c "VACUUM ANALYZE;"

# 完整 VACUUM（會鎖定表格，建議維護時段執行）
docker exec ai_investor-db-1 psql -U postgres -d ai_investor -c "VACUUM FULL ANALYZE;"
```

**索引重建**：

```bash
# 檢視需要重建的索引
docker exec ai_investor-db-1 psql -U postgres -d ai_investor -c "
SELECT indexrelname, pg_size_pretty(pg_relation_size(indexrelid)) as size
FROM pg_stat_user_indexes
WHERE idx_scan = 0
ORDER BY pg_relation_size(indexrelid) DESC;"
```

### 6.3 軟體更新程序

**更新步驟**：

```bash
cd /opt/ai-investor

# 1. 備份當前配置
cp docker-compose.yml docker-compose.yml.backup
cp .env .env.backup

# 2. 拉取最新映像
docker-compose pull

# 3. 查看變更
docker-compose config

# 4. 執行更新
docker-compose up -d

# 5. 驗證服務正常
docker-compose ps
curl -f http://localhost:8000/health

# 6. 監控新版本穩定性
docker logs -f api --since 10m
```

**回滾程序**：

```bash
cd /opt/ai-investor

# 1. 停止新版本
docker-compose down

# 2. 回復配置
cp docker-compose.yml.backup docker-compose.yml
cp .env.backup .env

# 3. 啟動舊版本
docker-compose up -d
```
