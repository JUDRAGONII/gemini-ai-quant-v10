# 臺灣證券、期貨、櫃買 OpenAPI 深度分析報告

## 1. 臺灣證券交易所 (TWSE) OpenAPI

* **API 網址**：`https://openapi.twse.com.tw/`
* **Base URL**：`https://openapi.twse.com.tw/v1`
* **主要功能分類**：
* **公司治理**：包含上市公司 ESG 資料、董事酬金、股東會資訊。
* **證券交易**：收盤行情、本益比/殖利率/淨值比、當沖標的、三大法人持股統計。
* **財務報表**：上市公司月營收、資產負債表、綜合損益表、營益分析。
* **指數/權證**：發行量加權指數、臺灣50指數歷史資料、權證基本資料。


* **使用方式限制**：
* **無須 API Key**：目前採開放格式，不需註冊或傳遞 Token。
* **呼叫頻率限制**：官方雖未在 Swagger 介面明確標示，但根據實務經驗與公平使用原則，建議頻率不超過 **每分鐘 30 次**。若高頻率存取會導致 IP 被暫時封鎖（429 Too Many Requests）。
* **資料格式**：主要提供 `JSON` 格式，部分路徑支援 `CSV` 下載。

## 2. 臺灣期貨交易所 (TAIFEX) OpenAPI

* **API 網址**：`https://openapi.taifex.com.tw/`
* **Base URL**：`https://openapi.taifex.com.tw/v1`
* **主要功能分類**：
* **行情資訊**：期貨/選擇權每日交易行情、最後結算價、Delta 值、Put/Call Ratio。
* **法人與部位**：三大法人部位（日/週）、大額交易人未沖銷部位、三大法人成交明細。
* **保證金資訊**：股價指數、利率、商品、股票類保證金一覽表。
* **統計資料**：市場參與者統計、期貨商交易量、各商品年成交量統計。


* **使用方式限制**：
* **OAS 3.0 標準**：使用 OpenAPI Specification 3.0。
* **資料延遲性**：此 API 提供的是盤後與統計資訊，**不適合**用於即時交易撮合系統（Real-time trading）。
* **限制規定**：根據「交易資訊使用管理辦法」，若將資料用於商業加值（如開發付費 App），需向期交所申請授權，不可隨意轉售原始數據。



---

## 3. 證券櫃檯買賣中心 (TPEx) OpenAPI

* **API 網址**：`https://www.tpex.org.tw/openapi/`
* **Base URL**：`https://www.tpex.org.tw/openapi/v1`
* **主要功能分類**：
* **上櫃/興櫃**：上櫃股票行情、本益比、三大法人買賣明細、當沖統計、興櫃市場現況。
* **債券/基金**：國際債券、公債發行資料、開放式基金行情、黃金現貨行情。
* **公司資訊**：企業 ESG、除權除息預告、重大訊息摘要。


* **使用方式限制**：
* **資料更新頻率**：收盤行情與三大法人資料通常在 **16:00~17:00** 之間更新完畢。
* **結構穩定性**：櫃買中心的 API 端點命名（Endpoint）較直覺（如 `tpex_mainboard_quotes`），適合建立自動化排程。
* **呼叫限制**：同 TWSE，應避免併發大量請求。

## AI 捕捉資料回填資料庫建議指令 (Prompt for AI)

**請將以下 Prompt 貼給 AI 工具：**

> 「請以此三組 OpenAPI 為數據源，設計一個資料捕捉程序（Python/TypeScript）。
> **任務需求：**
> 1. **資料對齊**：將 `TWSE` 與 `TPEx` 的『收盤行情』資料欄位對齊（如代號、名稱、收盤價、成交量），整合進同一個 `daily_quotes` 資料表。
> 2. **頻率控制**：實作 `Rate Limiter`，確保每秒請求次數 < 1，並在遇到 `HTTP 429` 時自動退讓（Exponential Backoff）。
> 3. **資料驗證**：在寫入資料庫（PostgreSQL/MySQL）前，驗證欄位是否為空（如當日停牌無資料處理）。
> 4. **排程邏輯**：產出一個每天下午 17:30 執行的 Cron Job 腳本，自動更新當日法人買賣超與期貨 `Put/Call Ratio`。
> 5. **異常告警**：若 API 回傳非 200 狀態碼，需記錄日誌並發送通知。」

### ⚠️ 共通技術規範與限制（核心重點）：

1. **時區**：所有資料皆以台灣時間 (UTC+8) 為準。
2. **安全性**：三家平臺目前均不支援 CORS 跨域直接請求（前端 JS 直連），建議透過 **Server-side (Node.js/Python)** 進行後端捕捉，以避免瀏覽器限制。
3. **流量策略**：由於這三家 API 均無提供「歷史資料區間下載」功能（大多僅提供最新資料），若要建立資料庫，建議**今日起每日排程存入**。
