## 2. 核心對接邏輯 (Integration Logic)

### 2.1 數據獲取 (Fetch)
所有對接均由 `ai-worker` 中的 `Fetcher` 類別執行：
*   **Tiingo 持續獲取**: 實作 `TiingoFetcher`，利用斷點續傳機制回補歷史數據。
*   **FRED 動態校準**: 針對指標代號變更（如 `UMCSENT`）實作中介映射層。

### 2.2 錯誤處理與退避 (Error Handling)
*   **HTTP 429**: 當觸發頻率限制，`Fetcher` 自動休眠並採用「指數退避 (Exponential Backoff)」策略。
*   **數據不一致**: 若同一交易日不同來源價格落差 > 0.5%，觸發「人工校驗日誌」。

---

## 3. 金融數據對接細節 (OpenAPI Spec)

### 3.1 臺灣證券交易所 (TWSE)
*   **主要端點**: `DailyQuotes`, `Bwibbk` (本益比/殖利率)。
*   **特性**: 無須個人 Key，但需嚴格控制併發數，避免 IP 被封鎖。

### 3.2 臺灣期貨交易所 (TAIFEX)
*   **主要端點**: `DailyMarketReportFut` (期貨行情)。
*   **格式**: 偵測並移除 `utf-8-sig` (BOM)，防止 JSON 解析失敗。

---

## 4. 安全與隱私保護

*   **API Key 脫敏**: 所有外部 API Key 嚴禁寫入程式碼，統一由 `.env` 或 Supabase Vault 注入容器環境變數。
*   **流量轉發**: 統一由 `ai-worker` 出站，地端 Nginx 不直接與外部 API 交互，隱藏系統指紋。
