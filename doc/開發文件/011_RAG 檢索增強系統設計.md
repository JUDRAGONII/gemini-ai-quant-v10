## 第一章：RAG 系統總覽

### 1.1 設計目標

RAG（Retrieval-Augmented Generation）檢索增強系統旨在解決大型語言模型的两大核心限制：知識截止問題與幻覺問題。透過即時檢索相關知識並注入模型上下文，系統能夠結合實時市場資訊與歷史知識庫進行分析，提供更準確、更可信的投資建議。

本系統的設計目標包括：存取並理解歷史 AI 報告（形成機構級的投資知識沉澱）、支援自然語言搜尋（用戶可用白話提問獲得專業回答）、減少模型幻覺（所有輸出皆可追溯至原始知識來源）、實現持續學習（每天新產出的報告自動加入知識庫）。

### 1.2 系統架構

RAG 系統由以下核心组件構成：

| 組件 | 功能 | 技術堆疊 |
|------|------|----------|
| 數據注入器 | 文本分塊與向量化 | Python + LangChain |
| 向量資料庫 | 儲存與檢索向量 | pgvector |
| 檢索引擎 | 混合檢索策略 | PostgreSQL RPC |
| 上下文合成器 | 構建最終 Prompt | Python PromptTemplate |
| 回饋系統 | 收集用戶評價 | PostgreSQL |

### 2.2 文檔分塊策略

文檔分塊（Chunking）是 RAG 系統的關鍵環節，適當的分塊策略能夠確保檢索結果的相關性與完整性。本系統採用「重疊滑動視窗」分塊策略：

```python
# rag/chunker.py

from langchain.text_splitter import RecursiveCharacterTextSplitter

class ReportChunker:
    def __init__(self, chunk_size=800, chunk_overlap=80):
        self.chunk_size = chunk_size
        self.chunk_overlap = chunk_overlap
        
        self.splitter = RecursiveCharacterTextSplitter(
            chunk_size=chunk_size,
            chunk_overlap=chunk_overlap,
            separators=["\n\n", "\n", "。", "！", "？", " ", ""],
            length_function=len
        )
    
    def split_report(self, report: Dict) -> List[Dict]:
        content = report['full_content']
        
        chunks = self.splitter.create_documents([content])
        
        chunked_data = []
        for i, chunk in enumerate(chunks):
            chunked_data.append({
                'report_id': report['id'],
                'stock_code': report['stock_code'],
                'chunk_index': i,
                'chunk_text': chunk.page_content,
                'chunk_metadata': {
                    'report_type': report['report_type'],
                    'generated_at': report['generated_at'],
                    'section': self._identify_section(chunk.page_content)
                }
            })
        
        return chunked_data
    
    def _identify_section(self, text: str) -> str:
        sections = {
            '投資摘要': ['摘要', 'summary', '結論'],
            '基本面分析': ['基本面', '財務', '營收', '獲利'],
            '技術分析': ['技術', '走勢', '均線', 'K線'],
            '籌碼分析': ['籌碼', '法人', '融資', '融券'],
            '風險因素': ['風險', '警告', '注意']
        }
        
        for section, keywords in sections.items():
            for keyword in keywords:
                if keyword in text:
                    return section
        return '其他'
```

### 2.3 向量化流程

向量化流程將文字內容轉換為高維向量，使語意相似性計算成為可能。系統使用 Gemini 的 `text-embedding-004` 模型產生 1536 維度的向量：

```python
# rag/embedder.py

from langchain_gemini import ChatGemini
from langchain_huggingface import HuggingFaceEmbeddings
import numpy as np
from typing import List

class ReportEmbedder:
    def __init__(self, model_name="text-embedding-004"):
        self.model_name = model_name
        self.embeddings = self._init_embeddings()
    
    def _init_embeddings(self):
        return HuggingFaceEmbeddings(
            model_name="sentence-transformers/all-MiniLM-L6-v2"
        )
    
    async def embed_texts(self, texts: List[str]) -> List[List[float]]:
        """將文字清單向量化"""
        embeddings = self.embeddings.embed_documents(texts)
        return embeddings
    
    async def embed_query(self, query: str) -> List[float]:
        """將查詢問題向量化"""
        embedding = self.embeddings.embed_query(query)
        return embedding
    
    async def embed_batch(self, chunks: List[Dict]) -> List[Dict]:
        """批次處理文塊向量化"""
        texts = [chunk['chunk_text'] for chunk in chunks]
        embeddings = await self.embed_texts(texts)
        
        for i, embedding in enumerate(embeddings):
            chunks[i]['embedding'] = embedding
        
        return chunks
```

### 3.2 HNSW 索引配置

HNSW（Hierarchical Navigable Small Worlds）是 pgvector 支援的最先進索引類別，提供优秀的查詢效能：

| 參數 | 建議值 | 說明 |
|------|--------|------|
| m | 16 | 索引的連接數，影響召回率 |
| ef_construction | 64 | 建立索引時的搜尋寬度，影響建立時間與品質 |

```sql
-- 建立 HNSW 索引（已於 Schema 中定義）
CREATE INDEX ON ai_report_chunks 
USING hnsw (embedding vector_cosine_ops) 
WITH (m = 16, ef_construction = 64);
```

### 3.3 向量距離度量

系統使用餘弦相似度（Cosine Similarity）作為向量距離度量：

$$ similarity(a, b) = \frac{a \cdot b}{\|a\| \times \|b\|} $$

pgvector 提供 `<=>` 運算子計算餘弦距離（越小越相似）：

```sql
-- 範例：檢索與查詢最相似的報告片段
SELECT 
    report_id,
    chunk_text,
    embedding <=> query_embedding AS distance
FROM ai_report_chunks
ORDER BY distance ASC
LIMIT 5;
```

## 第四章：混合檢索策略

### 4.1 檢索流程設計

系統採用「混合檢索」策略，結合向量檢索與關鍵字檢索的優勢，確保檢索結果既相關又全面：

```python
# rag/retriever.py

from typing import List, Dict, Tuple
import numpy as np

class HybridRetriever:
    def __init__(self, db_connection):
        self.db = db_connection
    
    async def retrieve(self, query: str, stock_code: str = None, 
                      top_k: int = 5) -> List[Dict]:
        # 1. 向量化查詢
        query_embedding = await self._embed_query(query)
        
        # 2. 並行執行向量檢索與關鍵字檢索
        vector_results = await self._vector_search(query_embedding, stock_code, top_k * 2)
        keyword_results = await self._keyword_search(query, stock_code, top_k * 2)
        
        # 3. 結果融合與重排序
        fused_results = self._fusion_rerank(vector_results, keyword_results)
        
        # 4. 回傳 Top-K
        return fused_results[:top_k]
    
    async def _vector_search(self, query_embedding: List[float], 
                            stock_code: str = None, limit: int = 10) -> List[Dict]:
        sql = """
        SELECT 
            id, report_id, stock_code, chunk_text, chunk_section,
            embedding <=> %s AS distance
        FROM ai_report_chunks
        WHERE %s IS NULL OR stock_code = %s
        ORDER BY embedding <=> %s
        LIMIT %s
        """
        params = (query_embedding, stock_code, stock_code, query_embedding, limit)
        
        results = self.db.query(sql, params)
        return [
            {
                'id': r['id'],
                'report_id': r['report_id'],
                'stock_code': r['stock_code'],
                'chunk_text': r['chunk_text'],
                'section': r['chunk_section'],
                'vector_score': 1 - r['distance'],  # 轉換為相似度
                'source': 'vector'
            }
            for r in results
        ]
    
    async def _keyword_search(self, query: str, stock_code: str = None,
                             limit: int = 10) -> List[Dict]:
        sql = """
        SELECT 
            id, report_id, stock_code, chunk_text, chunk_section,
            ts_rank(to_tsvector(chunk_text), query) AS rank
        FROM ai_report_chunks,
             to_tsquery('english', %s) AS query
        WHERE %s IS NULL OR stock_code = %s
          AND to_tsvector(chunk_text) @@ query
        ORDER BY rank DESC
        LIMIT %s
        """
        
        # 將查詢轉換為全文檢索格式
        tsquery = ' & '.join(query.split())[:100]
        params = (tsquery, stock_code, stock_code, limit)
        
        results = self.db.query(sql, params)
        return [
            {
                'id': r['id'],
                'report_id': r['report_id'],
                'stock_code': r['stock_code'],
                'chunk_text': r['chunk_text'],
                'section': r['chunk_section'],
                'keyword_score': r['rank'] / max(r['rank'], 1),
                'source': 'keyword'
            }
            for r in results
        ]
    
    def _fusion_rerank(self, vector_results: List[Dict], 
                       keyword_results: List[Dict]) -> List[Dict]:
        # 使用 Reciprocal Rank Fusion (RRF) 重排序
        rrf_k = 60
        
        combined = {}
        all_results = vector_results + keyword_results
        
        for rank, result in enumerate(all_results, 1):
            result_id = result['id']
            if result_id not in combined:
                combined[result_id] = result
                combined[result_id]['rrf_score'] = 0
            
            source = result['source']
            score = result.get('vector_score', 0) if source == 'vector' else result.get('keyword_score', 0)
            combined[result_id]['rrf_score'] += score * (1 / (rank + rrf_k))
        
        # 按 RRF 分數排序
        sorted_results = sorted(combined.values(), 
                               key=lambda x: x['rrf_score'], 
                               reverse=True)
        
        return sorted_results
```

### 4.2 RPC 檢索函數

系統定義 PostgreSQL RPC 函數供 API 調用：

```sql
-- match_reports: 基於向量相似度的報告檢索
CREATE OR REPLACE FUNCTION match_reports(
    query_embedding vector(1536),
    match_threshold float DEFAULT 0.7,
    match_count int DEFAULT 5,
    stock_code_filter varchar DEFAULT NULL
)
RETURNS TABLE (
    id bigint,
    report_id uuid,
    stock_code varchar(20),
    chunk_text text,
    chunk_section varchar(50),
    similarity float
)
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN QUERY
    SELECT 
        c.id, c.report_id, c.stock_code, c.chunk_text, c.chunk_section,
        1 - (c.embedding <=> query_embedding) AS similarity
    FROM ai_report_chunks c
    WHERE (stock_code_filter IS NULL OR c.stock_code = stock_code_filter)
      AND (1 - (c.embedding <=> query_embedding)) >= match_threshold
    ORDER BY c.embedding <=> query_embedding
    LIMIT match_count;
END;
$$;
```

### 4.3 意圖識別與查詢分類

系統對用戶輸入進行意圖識別，針對不同意圖採用不同的檢索策略：

| 意圖類型 | 範例問題 | 檢索策略 |
|----------|----------|----------|
| 估值分析 | "台積電現在估值合理嗎？" | 優先檢索估值相關段落 |
| 技術走勢 | "聯發科最近技術面如何？" | 優先檢索技術分析段落 |
| 風險評估 | "投資半導體有哪些風險？" | 優先檢索風險因素段落 |
| 綜合建議 | "可以買台積電嗎？" | 全方位檢索所有段落 |
| 產業比較 | "聯電跟台積電哪個好？" | 檢索兩家公司報告並對比 |

```python
# rag/intent_classifier.py

from enum import Enum

class QueryIntent(Enum):
    VALUATION = "valuation"
    TECHNICAL = "technical"
    RISK = "risk"
    RECOMMENDATION = "recommendation"
    COMPARISON = "comparison"
    GENERAL = "general"

class IntentClassifier:
    def __init__(self):
        self.intent_keywords = {
            QueryIntent.VALUATION: ['估值', '本益比', '股價淨值比', '貴', '便宜', '合理'],
            QueryIntent.TECHNICAL: ['技術', '走勢', '均線', 'K線', '圖型', '突破'],
            QueryIntent.RISK: ['風險', '注意', '警告', '擔心', '問題'],
            QueryIntent.RECOMMENDATION: ['買', '賣', '投資', '建議', '好嗎'],
            QueryIntent.COMPARISON: ['比較', '哪個', '還是', '差異']
        }
    
    def classify(self, query: str) -> Tuple[QueryIntent, float]:
        query_lower = query.lower()
        scores = {intent: 0 for intent in QueryIntent}
        
        for intent, keywords in self.intent_keywords.items():
            for keyword in keywords:
                if keyword in query_lower:
                    scores[intent] += 1
        
        best_intent = max(scores, key=scores.get)
        confidence = scores[best_intent] / max(sum(scores.values()), 1)
        
        return best_intent, confidence
```

### 5.1 上下文注入策略

檢索結果需要經過清洗與組織後注入 LLM Prompt，確保模型能夠有效利用檢索到的知識：

```python
# rag/context_builder.py

from langchain.prompts import PromptTemplate
from typing import List, Dict

class ContextBuilder:
    def __init__(self):
        self.system_prompt = """你是一位專業的投資分析師。請基於以下檢索到的相關歷史報告內容，回答用戶的問題。

## 檢索到的相關資訊：
{context}

## 用戶問題：
{query}

## 回答要求：
1. 基於檢索到的資訊進行回答，不要加入未經檢索確認的資訊。
2. 明確標注資訊來源的報告。
3. 如檢索結果不足以回答問題，請清楚說明。
4. 回答應結構清晰，邏輯嚴謹。
"""
    
    def build_context(self, query: str, retrieved_chunks: List[Dict]) -> str:
        if not retrieved_chunks:
            return "（本次查詢未找到直接相關的歷史報告，將基於一般知識回答）"
        
        context_parts = []
        for i, chunk in enumerate(retrieved_chunks, 1):
            context_parts.append(
                f"【來源 {i}】({chunk['section']})\n"
                f"相關度：{chunk.get('rrf_score', chunk.get('vector_score', 0)):.2f}\n"
                f"{chunk['chunk_text']}"
            )
        
        return "\n\n".join(context_parts)
    
    def create_prompt(self, query: str, retrieved_chunks: List[Dict]) -> str:
        context = self.build_context(query, retrieved_chunks)
        
        return self.system_prompt.format(
            context=context,
            query=query
        )
```

```python
# rag/cache.py

from cachetools import TTLCache
import hashlib

class RetrievalCache:
    def __init__(self, ttl_seconds=3600, max_size=1000):
        self.cache = TTLCache(max_size=max_size, ttl=ttl_seconds)
    
    def _generate_key(self, query: str, stock_code: str = None, top_k: int = 5) -> str:
        key_string = f"{query}:{stock_code}:{top_k}"
        return hashlib.md5(key_string.encode()).hexdigest()
    
    def get(self, query: str, stock_code: str = None, top_k: int = 5):
        key = self._generate_key(query, stock_code, top_k)
        return self.cache.get(key)
    
    def set(self, query: str, result: List[Dict], stock_code: str = None, top_k: int = 5):
        key = self._generate_key(query, stock_code, top_k)
        self.cache[key] = result
```

### 6.3 異步處理

```python
# rag/async_pipeline.py

import asyncio
from typing import List
from concurrent.futures import ThreadPoolExecutor

class AsyncRAGPipeline:
    def __init__(self, max_workers=4):
        self.executor = ThreadPoolExecutor(max_workers=max_workers)
        self.embedder = ReportEmbedder()
        self.retriever = HybridRetriever()
    
    async def process_query(self, query: str, stock_code: str = None) -> Dict:
        # 並行執行向量化與意圖分類
        embedding_task = self.executor.submit(
            asyncio.run, self.embedder.embed_query(query)
        )
        intent_task = self.executor.submit(
            self.retriever.classifier.classify, query
        )
        
        query_embedding = embedding_task.result()
        intent, confidence = intent_task.result()
        
        # 執行檢索
        chunks = await self.retriever.retrieve(
            query, stock_code, top_k=5
        )
        
        # 構建上下文
        context = self.context_builder.create_prompt(query, chunks)
        
        return {
            'intent': intent.value,
            'confidence': confidence,
            'context': context,
            'sources': [c['report_id'] for c in chunks]
        }
```

### 附錄 B：常見問題與解決方案

| 問題 | 可能原因 | 解決方案 |
|------|----------|----------|
| 檢索結果不相關 | 分塊策略不佳 | 調整 chunk_size 或 overlap |
| 向量化耗時過長 | 批次處理不足 | 增加批次大小或使用更快模型 |
