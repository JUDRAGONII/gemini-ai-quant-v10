# 011_RAG 檢索增強系統設計

**文件編號**：AI-V10.0-002
**版本**：2.0.0
**建立日期**：2026-02-25
**核心技術**：pgvector (Supabase) + text-embedding-3-small (Gemini)

---

## 1. RAG 管線與數據流 (The Pipeline)

系統透過「預處理 -> 向量化 -> 檢索 -> 合成」四階段，讓 AI 具備長期記憶。

### 1.1 數據注入 (Ingestion)
*   **對象**：`ai_reports` 表中的 `full_content` 欄位。
*   **分塊 (Chunking)**：每份報告按 800 tokens 進行重疊分塊 (Overlap 10%)。
*   **向量化**：呼叫 Gemini API 產出 1536 維度向量。

### 1.2 檢索機制 (Retrieval)
*   **Cosine Similarity**: 透過 PostgreSQL `rpc/match_reports` 執行餘弦相似度計算。
*   **Top-K**: 每次查詢取前 5 筆最相關片段。

---

## 2. 向量資料庫配置 (pgvector)

### 2.1 索引與效能
*   **Index Type**: HNSW (Hierarchical Navigable Small Worlds)。
*   **衡量標準**: Cosine Distance (`<=>` operator)。

### 2.2 Schema 整合
```sql
ALTER TABLE ai_reports ADD COLUMN embedding vector(1536);
CREATE INDEX ON ai_reports USING hnsw (embedding vector_cosine_ops);
```

---

## 3. 合成與回答 (Synthesis)

*   **Prompt 注入**：將檢索到的報告片段作為 "Context" 注入 LLM Prompt。
*   **事實驗證 (Grounding)**：要求 LLM 在回答中明確指出資訊來源於哪一份歷史報告，避免幻覺。
