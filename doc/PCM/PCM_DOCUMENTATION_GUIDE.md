# PCM 文件結構化指南

**文件編號**：DOC-V10.0-PCM-GUIDE
**版本**：1.0.0
**建立日期**：2026-02-06
**目的**：說明 PCM 文件的結構化標準與使用方法

---

## 一、概述

本指南旨在規範 AI 投資分析儀 V10.0 專案的 PCM（Phase Control Matrix）文件體系，確保文件的結構化、規則化與可維護性。

### 1.1 PCM 文件體系

| 文件 | 用途 | 維護頻率 |
|------|------|----------|
| 0-0_V10.0_Phase_Control_Matrix.md | 階段控制矩陣 | 每 Phase 更新 |
| 0-1_DEV_SUMMARY.md | 開發摘要與待辦 | 每週更新 |
| 0-2_CHANGELOG.md | 變更紀錄 | 每次發布更新 |

### 1.2 文件模板

| 模板文件 | 用途 |
|----------|------|
| PCM_TEMPLATE_PHASE_CONTROL_MATRIX.md | 階段控制矩陣模板 |
| PCM_TEMPLATE_DEV_SUMMARY.md | 開發摘要模板 |
| PCM_TEMPLATE_CHANGELOG.md | 變更紀錄模板 |

### 1.3 參考範例

| 範例文件 | 用途 |
|----------|------|
| PCM_EXAMPLE_PHASE_CONTROL_MATRIX.md | 結構化 PCM 範例 |
| PCM_EXAMPLE_DEV_SUMMARY.md | 結構化 DEV_SUMMARY 範例 |
| PCM_EXAMPLE_CHANGELOG.md | 結構化 CHANGELOG 範例 |

## 四、階段控制矩陣結構

### 4.1 必要章節

```
一、專案總覽
   1.1 專案基本資訊
   1.2 技術架構
   1.3 專案時程總覽

二、已完成階段詳情
   Phase X: [階段名稱]
      - 階段目標
      - 驗收標準
      - 工作分解結構
      - 交付成果
      - 風險與議題

三、待執行階段
   Phase X: [階段名稱]
      - 階段目標
      - 驗收標準
      - 工作分解結構
      - 交付成果
      - 風險與議題

四、關鍵里程碑
五、依賴關係
六、附錄
```

### 4.2 狀態標記

| 狀態 | 標記 | 說明 |
|------|------|------|
| 未開始 | ⏳ | 尚未開始執行 |
| 進行中 | 🔥 | 正在執行中 |
| 已完成 | ✅ | 已經完成驗收 |
| 已暫停 | ⏸️ | 因故暫停執行 |

## 五、開發摘要結構

### 5.1 必要章節

```
一、文件目的
二、使用說明
三、專案現況摘要
   3.1 整體進度
   3.2 當前任務
四、待辦清單
   Priority 0-3
五、執行歷程
六、問題與教訓
   6.1 已解決問題
   6.2 待解決問題
   6.3 經驗教訓
七、後續提醒
八、附錄
```

### 5.2 優先級定義

| 優先級 | 說明 | 處理時機 |
|--------|------|----------|
| P0 | 阻礙專案推進 | 立即處理 |
| P1 | 重要功能缺失 | 本 Sprint 處理 |
| P2 | 建議改進項目 | 下一 Sprint 處理 |
| P3 | 錦上添花 | 有餘力時處理 |

## 六、變更紀錄結構

### 6.1 版本標題格式

```markdown
## [X.X.X] - YYYY-MM-DD
```

### 6.2 變更分類

| 類型 | 說明 | 範例 |
|----------|------|------|
| Added | 新增功能 | 新增使用者註冊功能 |
| Changed | 現有功能變更 | 修改 API 回應格式 |
| Deprecated | 廢棄功能 | 標記 v1 API 為廢棄 |
| Fixed | 錯誤修復 | 修復登入 Session 問題 |
| Security | 安全性相關 | 修復 SQL Injection 漏洞 |
| Removed | 移除功能 | 移除舊版 API 端點 |

### 6.3 版本號規範

| 版本類型 | 說明 | 範例 |
|----------|------|------|
| Major | 重大變更，可能影響相容性 | 1.0.0 → 2.0.0 |
| Minor | 新功能，向後相容 | 1.0.0 → 1.1.0 |
| Patch | 錯誤修復，向後相容 | 1.0.0 → 1.0.1 |

## 七、文件維護規範

### 7.1 更新頻率

| 文件 | 更新時機 |
|------|----------|
| Phase Control Matrix | 每 Phase 開始/結束時 |
| DEV_SUMMARY | 每週至少一次 |
| CHANGELOG | 每次發布或部署後 |

### 7.2 審核流程

1. **草稿**：開發人員填寫
2. **審核中**：技術負責人審核
3. **正式**：審核通過，發布使用

## 八、常見問題

### Q1: 如何新增一個 Phase？
A1: 在 Phase Control Matrix 的「待執行階段」章節新增區塊，遵循相同結構。

### Q2: 如何記錄一個 Bug Fix？
A2: 在 CHANGELOG 中新增 `### Fixed` 區塊，描述問題與解決方案。

### Q3: 待辦項目狀態如何標記？
A3: 使用 `[ ]` 表示待辦，`[x]` 表示完成，標記格式應與模板一致。
