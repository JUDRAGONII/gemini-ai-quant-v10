## CHANGELOG 撰寫指南

### 1. 撰寫原則

- **及時性**：每次發布或部署後立即更新
- **一致性**：使用統一的格式和命名規範
- **可讀性**：簡潔明瞭，方便閱讀
- **完整性**：涵蓋所有類型的變更

### 2. 撰寫時機

- 新功能開發完成
- 錯誤修復
- 效能優化
- 安全性更新
- 相容性變更

### 3. 審核流程

1. 開發人員填寫變更內容
2. 技術負責人審核
3. 更新版本號
4. 發布 CHANGELOG
