# Phase 11.4 測試案例：ETL 擴充與規格對齊

## 測試目標
驗證 `EconomicEventFetcher` 的數據擷取準確性、資料庫寫入一致性，以及 API 欄位對齊情形。

## 測試環境
- Backend: Python 3.13 / FastAPI
- Database: Supabase (PostgreSQL)

## 測試案例清單

### 1. 基礎路徑 (Basic Path)

### 2. 邊界條件 (Boundary Conditions)
- [ ] **TC-ETL-2001: API 空值與異常模擬**
    - **步驟**: 使用 Mock 模擬 FRED API 回傳空列表或 404。
    - **預期**: Fetcher 應記錄 Error 並優雅退出，不發生 Crash。
- [ ] **TC-ETL-2002: 重複事件冪等性驗證**
    - **步驟**: 連續兩次寫入相同 `event_code` 與 `scheduled_at` 的事件。
    - **預期**: 資料庫應執行 `upsert`，總筆數不增加。

### 3. 安全性與 RLS (Security)
- [ ] **TC-SEC-3001: 經濟日曆匿名讀取權限**
    - **步驟**: 使用 `anon` Key 調用 API。
    - **預期**: 應能成功讀取日曆數據。
- [ ] **TC-SEC-3002: 服務角色寫入權限**
    - **步驟**: 模擬 `service_role` 權限進行寫入。
    - **預期**: 寫入成功。

### 4. UX 相關驗證 (UX Alignment)
- [ ] **TC-UX-4001: 重要性過濾測試**
    - **步驟**: 調用 API 並帶入 `min_importance=5`。
    - **預期**: 回傳結果應僅包含高等級事件。
