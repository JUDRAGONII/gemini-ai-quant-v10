# 20260120_Phase2_後端邏輯驗收

本文件旨在驗證 Phase 2 後端邏輯實作的完整性與健壯性。測試範圍涵蓋 ETL 模組、AI 辯論引擎與系統排程。

## 測試案例清單

### 1. 基礎路徑驗證 (Basic Path)
- [x] **ETL 資料完整性**: 執行 `MacroETL.run()` 後，查詢 `macro_indicators` 表，確認 GDP、CPI、VIX 等指標在最近 30 天內有數據紀錄。
- [x] **AI 報告生成**: 執行 `DialecticAgent.conduct_debate("Test Topic")` 後，查詢 `ai_reports` 表，確認新增了一筆包含 `[BULL]`, `[BEAR]`, `[SYNTHESIS]` 區塊的報告。
- [x] **Supabase 單例模式**: 驗證 `get_supabase()` 在多次呼叫下回傳相同的 Client Instance (Memory Address 相同)。
- [x] **Prefect 排程啟動**: 執行 `daily_pipeline()`，確認其子任務 (`Sync Macro Data`) 狀態回傳為 Completed。

### 2. 邊界條件與異常處理 (Boundary & Exception)
- [x] **FRED API 金鑰缺失**: 暫時移除 `FRED_API_KEY` 環境變數，執行 ETL，驗證程式應輸出警告但不應崩潰 (Graceful Failure)。
- [x] **Gemini Quota Exceeded**: 模擬/觸發 429 Rate Limit，驗證 `DialecticAgent` 能捕捉異常並記錄錯誤日誌，而非導致 Worker 服務重啟。
- [x] **重複資料處理 (Idempotency)**: 連續執行兩次 `MacroETL.run()`，驗證 `macro_indicators` 總筆數不應倍增 (Upsert 機制生效)。

### 3. 安全性與配置驗證 (Security & Config)
- [x] **Config 驗證機制**: 清空 `SERVICE_ROLE_KEY` 並載入 `Config` 模組，驗證應拋出 `ValueError` 防止服務在不安全狀態下啟動。
- [x] **RLS 寫入權限**: 確保 Backend 使用 `SERVICE_ROLE_KEY` 可寫入 `macro_indicators`，但若使用 `ANON_KEY` 初始化 Client 則應被拒絕寫入 (需模擬)。
