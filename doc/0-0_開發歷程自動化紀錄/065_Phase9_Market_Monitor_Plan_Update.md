### 🔍 問題診斷 (Root Cause Analysis)
1. **API 配額限制**: 原計畫中的「秒級實時報價」對於免費 API KEY 池 (Fugle, Tiingo) 壓力過大，容易觸發 429 錯誤或耗盡全日配額。
2. **資源競爭**: 系統背景同時存在「數據回補」、「AI 模型推理」與「自選股監控」等任務，均需消耗相同的 API 配額。
3. **穩定性考量**: 在免費額度下，維持全市場（2600+ 標的）的極低延遲更新是不切實際的，且增加系統複雜度。

### 🛠️ 執行動作 (Actions Taken)
1. **實作計畫修訂 (Archiving & Plan Sync)**:
    - 修改 `doc/plans/034_Phase9_Market_Monitor_Screener_Plan.md`。
    - 將「實時報價中繼 (Real-time Relay)」重命名為「**效能平衡報價中繼 (Quota-Balanced Market Relay)**」。
    - 更新機制為：預設 **每 30 分鐘** 更新一次全市場行情。
    - 引入「**配額感知與分層更新**」策略：
        - 自選股 (Watchlist)：15 分鐘/次。
        - 全市場標的：30-60 分鐘旋轉回補。
2. **技術規格調整**:
    - 移除 WebSocket 串流方案（暫不對接）。
    - 確定使用 `QuotaManager` 進行 API 頻率動態管制，優先保障 P0 級分析任務。
