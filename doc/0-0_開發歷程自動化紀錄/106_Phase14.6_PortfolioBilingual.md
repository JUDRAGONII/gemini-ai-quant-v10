# 開發日誌：Phase 14.6 投資組合全繁體中文化與字體 UI 修復

## 📅 日期: 2026-03-02
## 🎯 里程碑: Phase 14.6 

### 1. 需求解構與架構審查
- **需求**：依據使用者 UI 提案 (以圖表述名稱與描述的 Label 給予過小比例尺, 要求與持有清單看齊)，同時全面實做全繁體雙語化，並確定投資組合功能前後端串接狀況。
- **後端狀態**：`portfolios` 系列的服務 (`/api/portfolios/*`) 因資安與整合考量實作於 Next.js Backend-for-Frontend (BFF) Auth 環境下，並已接通 Supabase。**無需調整資料庫**。

### 2. UI 修復執行細節
- **原先問題**：使用者回報紅框 (`label` 名稱/描述) 的字體預設為 `text-[10px]`。在桌機版面中此字體會成為比 Placeholder 還微弱的裝飾詞，對比於下方主要表尾 (`text-xl font-bold`) 顯得不一致。
- **對策施作**：在 `app/portfolios/page.tsx` 中將 `label` CSS 改為：`"text-xl font-bold flex items-center gap-2 text-white ml-1"`。強化欄位識別。

### 3. 全端雙語化 (Bilingual)
1. **`app/portfolios/page.tsx` 主頁**：
   - 使用 `<Bilingual zh="x" en="y" mode="inline" />` 無縫轉換。
2. **`app/portfolios/[id]/page.tsx` 明細頁**：
   - 從副標題、新增持股表單（無狀態警示）至下面全部的 `table` `<thead>` 繁體硬代碼。
3. **`components/Chart/PortfolioPerformanceChart.tsx` 圖表**：
   - 圖表頂部區間 Filter：「1W、1M」與 Tooltip 內諸如「報酬金額」、「總價值」等均掛上 Bilingual 元件包裹。

### 4. 錯誤排除與預防方針
1. **【問題現象】**：`npm run build` 或 `tsc` 時噴發 TS2322 錯誤：指出 `<Bilingual zh={...}>` 中的 `zh` 參數限定收受 `string` 但我們卻傳入了 `<>xx<span>...</span></>` 的 React 虛擬 DOM Element。
2. **【根本原因】**：`Bilingual` 本身 `Props` 規定 `zh: string`。我們在抽離硬編碼時試圖把原版的漸層 Span 直接塞給 `zh` 屬性。
3. **【預防 Checkbox】**：
   - [x] 在遇見複合字型（同列有各種粗細不同的裝飾字）時，我們必須：將 `<Bilingual>` 當作純文字抽出。維持架構如 `<Bilingual zh="大標" /> <span style="...">裝飾字</span>` 而不是把它包進去。
