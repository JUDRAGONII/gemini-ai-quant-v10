# 開發日誌：Phase 14.5 市場動態全繁體中文化

## 📅 日期: 2026-03-02
## 🎯 里程碑: Phase 14.5

### 1. 需求解構
- **目標**：檢閱 `/app/market` 模組，分析前後端資料狀態，並執行介面的全面繁體中文化 (Bilingual)。

### 2. 底層分析與決策
- **資料流現況**：非常完美，前端已使用 `useHeatmap` (SWR) 向 `GET /api/v1/market/heatmap` 抓取聚合過後的真實市場階層報價 (`industry`, `sector`)，並且渲染正確形狀。
- **UI 現況**：存在嚴重的 Hardcoded 硬編碼繁體中文問題。
- **策略**：依照 KISS 原則，**完全不更動資料層與後端結構**。僅於前端 `MarketPage`, `MarketHeatmap` 以及周邊的 `AlertPanel` 等隱藏元件匯入 `<Bilingual>`，給予 `zh` 與 `en` 屬性即可。

### 3. 執行細節
1. **`MarketPage` 主頁**：
   - 包含主副標題、所有過濾器 (`ALL/TWSE`, `Sector/Industry`) 標籤均採用 `<Bilingual mode="inline" />` 無痛置換。
2. **`MarketHeatmap` 熱力圖**：
   - Treemap 的工具提示框 (Tooltip) 內部顯示價格、漲跌幅及成交量前戳加入 `<Bilingual>`，提升 UI 質感。
3. **`AlertPanel` 警示面板**：
   - 防禦性雙語化，這包括了諸如「市場監控中心」、「全部已讀」、「無異動」等預設狀態語言，確保組件於全站任何位置呼叫均保持語言一致。
4. **測試執行**：
   - 編譯端：透過 `npx tsc --noEmit` 確認套用 `<Bilingual>` 後 Type 安全無虞。
   - 測試端：`npm run test` 在 43 套件下總計 193 項滿分 PASS 通過，驗證 UI 改動沒有帶給元件狀態任何破壞。

### 4. 錯誤防範紀錄 (Lessons Learned)
- **問題**：若非使用 `mode="inline"` 屬性，`<Bilingual>` 預設為呈現 div 區塊模型 (Block Level)。
- **原因**：對於原本採用 `flex items-center` 同列排版的文字或圖示，注入 `<Bilingual>` 卻未特別處理將造成文字推擠或換行折斷。
- **對策**：在多數 `<Bilingual>` 被嵌入 `<span>` 或 `<h1>` 與 icon 並排的地方，務必顯式給予 `mode="inline"` 標籤來防止佈局跑位。
