# 🛡️ Phase 13.4: 法人級風險控系統 (Institutional Risk Management)

## 1. 需求解構 (Requirement Deconstruction)
**目標**：導入機構級的風險監控工具，包括 Greeks 敏感度分析、Barra 因子歸因與壓力測試，提升 AI 投研系統的核心競爭力與專業質感。

## 2. 實作細節 (Implementation Details)

### 後端實作 (Backend)
- **`RiskService`**: 實作於 `backend/services/risk_service.py`。
    - **Greeks 模擬**: 基於價格與因子波動性，模擬 Delta, Gamma, Theta, Vega 指標。
    - **Barra 風格分解**: 整合 18 因子數據，計算標的在規模、價值、動能、波動與成長維度的曝險權重。
    - **壓力測試**: 預設歷史極端場景（2008 金融海嘯、2020 COVID 熔斷等），分析預期最大回撤與恢復週期。
- **Professional API**: 新增 `backend/api/routers/professional.py` 路由。
    - 端點: `GET /api/v1/professional/risk-matrix`
    - 特點: 支援 Redis 快取 (TTL 1hr)，大幅提升熱點標的讀取效能。

### 前端實作 (Frontend)
- **`GreeksMonitor.tsx`**: 採用熱圖矩陣視覺化，直觀展示四維 Greeks 指標，符合 UI/UX Pro Max 規範。
- **`PsychologyHub.tsx`**: 結合 AI 偵測技術，量化用戶投資心理偏誤（損失厭惡、近親偏誤），並提供專家建議。
- **`RiskManagementPage`**: 位於 `/ai/risk`，作為法人級風控終端的主入口。
- **組件遷移**: 全面採用 `ProInput` 與 `ProButton` 旗艦級原子化組件，確保視覺統一與型別安全。

## 3. 驗證結果 (Verification Results)

## 4. 關鍵問題與解決方案
- **【問題】**: 原生 `Bilingual` 組件不支援 `size` 與 `color` 屬性，導致 `tsc` 報錯。
- **【解決】**: 將屬性傳遞邏輯回歸 `className` 與 `enClassName` 模式，維持組件庫的簡潔性 (KISS)。
- **【問題】**: `@/` 路徑別名在深度嵌套目錄 (L3+) 下解析不穩定。
- **【解決】**: 統一改用相對路徑 `../../` 或 `../../../` 導入，消除編譯器疑慮。
