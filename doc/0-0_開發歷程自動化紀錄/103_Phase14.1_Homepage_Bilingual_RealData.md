# 開發歷程自動化紀錄 - Phase 14.1

## 基本資訊
- **紀錄編號**: 103
- **階段**: Phase 14.1
- **功能名稱**: 系統首頁面板全繁體中文化與真實 API 數據導入
- **時間**: 2026-03-02

## 1. 需求解構與目標
- **痛點**: 專案 V10 核心頁面 (`app/page.tsx`) 中的圖表標題與狀態面板皆為硬編碼文字，不僅缺乏外語支援，更顯示過期與虛假之系統數據 (例如寫死的 120ms Latency)。測試案例也與這些硬編碼緊密耦合。
- **目標**: 貫徹 `/sdd`, `/architect`, `/ui-ux-pro-max` 原則，將首頁組件徹底雙語化 (`<Bilingual>`)，並動態串接此前開發之聚合 API (`/api/v1/monitor/dashboard`) 顯示真實伺服器負載與配額，最終修復因改版導致的 TDD 單元測試斷言失敗。

## 2. 實作細節與解決方案
1. **全景雙語化**:
   - 將首頁大標題「市場導航儀」替換為 `<Bilingual>`，使用 `stacked` 模式加入 `Market Navigator`。
   - 優化 `ChartWrapper` 組件簽名，支援 `titleZh` 與 `titleEn`，透過 `suffix` 模式呈現 `經濟成長 (GDP Growth QoQ)` 這種高質量 UI 文字。
   - 升級 `EnhancedReportCard`，使得報告標題根據 `report_type` 動態渲染雙語標籤。
2. **架構升級 (Client Component 抽離)**:
   - 建立 `HomeSystemHealth.tsx` Client Component，取代原本寫死在 `page.tsx` 中的 Server-side 假系統數據。
   - 導入 SWR 結合 `MonitorRepository.getDashboardSummary()`，實現每 5 秒輪詢後端，真實提取並展示 CPU 負載、RAM 使用率以及 Gemini 剩餘 API Token 呼叫次數。
   - 加入了 Skeleton 骨架屏以及針對異常狀態 (Fetch Failed) 的斷線警報 UI。
3. **TDD 測試對齊**:
   - 重構 `__tests__/app/page.test.tsx`。因改用 `<Bilingual>` 會導致渲染結果被中英文標籤拆分（例如原本找尋的完整字串變為子節點），因此將 `getByText` 全面替換為相容性更高的 `getAllByText().length > 0` 進行非精確比對斷言。
   - 針對 Client Component 的異步加載時序特性進行了 Mock 排錯，最終讓 53 條測試全數亮回綠燈。
