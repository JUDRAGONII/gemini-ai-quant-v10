# Phase 14.6 — 投資組合 (Portfolio) 全繁體中文化與真實數據深度審查

## 1. 🔍 當前專案狀況分析

### 後端架構 (Data Layer)
- 【架構設計】：不同於 `chips` 或 `insights` 使用 FastAPI (`backend/api/routers`)，`portfolios` 模組直接採用了 **Next.js API Route Handlers** (`app/api/portfolios/route.ts` 等)。
- 【資料真實性】：我們檢驗了 API 原始碼，此部分**完全串接真實數據庫 (Supabase `user_portfolios`, `holdings`)**。包含了 RLS 及 Supabase Auth 權限驗證，並非硬編碼 MOCK。
- 【結論】：**後端與 API 層無需任何重大結構修改**。符合資安與真實數據的需求。

### 前端架構 (UI/UX)
- 【硬編碼】：與前幾次模組相同，目前所有包含 `app/portfolios/*` 下面的標題、列表標籤、提示語、防護確認警告 (`alert`)，包含 Chart 都是完全的 Hard-coded 繁體中文，缺乏多國語言的彈性相容。
- 【排版體驗缺失】：**使用者發現（紅框標註之問題）**，投資組合首頁上方「建立組合」的 `<input>` 被給予了一個非常小、有失比例的 `<label className="text-[10px]">名稱 / 描述</label>`。對比下方的 `<h1>持有列表</h1>` (text-xl)，頭重腳輕非常嚴重，不符 UI Guidelines 中的 readability 與 hierarchy。

## 2. ⚡ 實踐計畫 (Implementation Plan)

### UI 優化指令 (Fixing the Red Box)
對於 `app/portfolios/page.tsx` 第 140 行左右的 `<label>`：
```tsx
// 舊
<label className="text-[10px] font-bold uppercase text-gray-400 ml-1">
// 新
<label className="text-xl font-bold flex items-center gap-2 text-white mb-2">
    <Bilingual zh="名稱" en="Portfolio Name" />
</label>
// 對齊綠框 (text-xl font-bold) 以確保表單在畫面中的存在感相等。
```

### 全端繁體中文化 / 雙語包裹 (Bilingual Wrapper Wrapper)
1. **`app/portfolios/page.tsx` (列表首頁)**:
   - 全面植入 `<Bilingual mode="inline">` 於標題：「我的投資組合」、「管理您的多維度投資組合...」、「輸入組合名稱」、「建立」、「持有列表」、「尚未建立任何投資組合」。
   - 代碼內的 `alert()`, `confirm()` 因為原生的限制無法使用 React Component，將維持或使用雙語字串。
2. **`app/portfolios/[id]/page.tsx` (投資組合內頁)**:
   - 同上實施 UI Component 解析與轉換，如 `總資產`, `歷史報酬`, `持股清單`, `新增交易` 等等。
3. **`components/Chart/PortfolioPerformanceChart.tsx`**:
   - `Tooltip` hover states 與 `Legend` 轉換。
