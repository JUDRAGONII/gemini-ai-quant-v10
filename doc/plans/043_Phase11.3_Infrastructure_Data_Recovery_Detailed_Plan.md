# Phase 11.3: 基礎設施與數據物理恢復 (Infrastructure & Data Recovery) 詳細計畫

## 1. 任務目標 (Executive Summary)
本子計畫旨在解決「物理審計 080」中識別出的 P0 級風險：**數據真空 (Data Vacuum)**。我們將重塑資料庫的地核動力，確保系統從「空殼」轉化為具備 **全歷史 (Full History)** 大數據支撐的「實體」。

## 2. 系統架構變更 (Architectural Changes)
採用 `/architect` 視角進行底層加固：

### 2.1 [NEW] [SQL] 數據結構恢復
*   **目標**: 重建遺失的 `exchange_rates` (匯率/貴金屬) 表。
*   **規格 (SDD Alignment)**:
    - 表名: `public.exchange_rates`
    - 欄位: `currency_pair` (Unique), `rate`, `reference_date` (Unique), `source`.
    - 索引: `idx_fx_pair_date` ON (currency_pair, reference_date DESC).

### 2.2 [FIX] 數據分區與索引校準
*   針對 `daily_price` 進行 `ANALYZE` 並驗證分區 (y1990-y2027) 是否全數掛載。

## 3. 執行路徑 (Execution Path)

### 第一階段：標的與匯率重建
1.  **[DDL]** 執行 `20260205_create_exchange_rates.sql`。
2.  **[Init]** 執行 `python backend/scripts/init_stock_list.py`。
    - 預期結果: `stocks` 表填入 2500+ 筆標的。

### 第二階段：宏觀與基準匯率回補 (The Benchmark)
1.  **[Backfill]** 執行 `python backend/scripts/backfill_macro.py`。
    - 覆蓋: 130+ FRED 指標 (**全歷史 1990+ 或更早**)。
    - 覆蓋: USD/TWD, USD/CNY, DXY。

### 第三階段：大行情灌漿與「極限全歷史」探測 (The Mass Fill & Deep Probe)
1.  **[Strategy]** 實作 **「跨世代」雙軌回補機制**:
    - **第一分界點**: **2004-02-11** (TWSE 官方數位化 JSON 起點)。
    - **第二分界點 (極限探測)**: **1990-01-01** (甚至更早，依 Free API 支持極限)。
    - **數據源選擇**:
        - **1990 以前 ~ 2004**: 優先採用 **Yahoo Finance (yfinance)**。針對台股大盤指數 (`^TWII`) 嘗試下探至 **1970 以前**。
        - **2004 ~ 至今**: 採用 **TWSE 官方 API (TwseHistoricalFetcher)** 確保權威精度。
2.  **[Backfill]** 使用 `BackfillManager` 與優化後的 Fetcher。
    - **美股 (Tiingo/Yahoo)**: 追溯至 **1990-01-01** 或標的上市日。
    - **台股 (Dual Mode)**: 
        - [Legacy Probe] 1990-2004: Yahoo Finance ( yfinance )。
        - [Official] 2004-Present: TWSE JSON API。
    - **期貨 (Taifex)**: 追溯至 **2001-01-01** (主力合約)。
    - **宏觀指標 (FRED)**: 使用 `.env` 中的 FRED Key，追溯至各指標之 **歷史極限日** (如 FEDFUNDS 可至 1954-07-01)。
