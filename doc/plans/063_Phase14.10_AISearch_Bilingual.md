# Phase 14.10 AI 搜尋 (AI Search) 雙語化與測試補齊計畫

AI 語義搜尋中心 (`app/ai/search`) 透過 RAG (Retrieval-Augmented Generation) 知識庫引擎，讓使用者能透過自然語言檢索投資報告與市場數據。

## 專案現況深度剖析 (Current State Analysis)

### 1. 資料源與業務邏輯 (Backend / API Layer)
- **現狀極佳**：該模組的前端會將搜索詞傳遞給本地路由 `/api/rag/search`。
- 這個路由內部會執行 `fetch('http://ai-api:8001/api/v1/rag/search')`，將任務完美轉交給了 Python 端基於向量存儲的。
- 測試報告顯示，連線非常平穩且回傳資料均為真實文檔比對（無 Mock Data），具有 100% 實戰能力。

### 2. 前端介面靜態文字雙語化缺失
多數文字在 `page.tsx` 開發初期被硬編碼以繁體中文撰寫，需升級以配合系統全球化：
- **搜尋欄與最近搜尋區塊**:
  - `請輸入問題，例如：半導體產業未來的成長動能為何？`
  - `最近搜尋`, `清除`
- **狀態與結果顯示**:
  - `搜尋`, `正在搜尋知識庫...`, `沒有找到相關結果`, `嘗試使用不同的關鍵字或更廣泛的描述`
  - `找到 X 個相關結果`
  - `相似度`, `展開全文`, `收合`

### 3. TDD 單元保險網狀況
- **缺失**：經過專案掃描，我發現目前並不存在針對 `app/ai/search/page.tsx` 的 Jest 測試檔案。相關測試覆蓋率為 0%。

## 預期改動與實作計畫 (Implementation Plan)

為維持整體的專業度與使用一致性，實踐防禦型 TDD 的最高準則。

### 階段一：精細化 UI 雙語補全 (Bilingual Enhancement)
#### [MODIFY] `app/ai/search/page.tsx`
- 將所有使用者能看到的介面文案利用 `<Bilingual>` 重構，以堆層或內聯 (mode="inline" / "stacked") 的方式展示，使其能像先前的其他模組一樣即時切換與並列呈現。

### 階段二：TDD 單元測試保險防護 (Test Coverage)
#### [NEW] `__tests__/app/ai/search/page.test.tsx`
- 模擬搜尋流程：輸入 -> 回車/點擊 -> 出現載入中 (Spinner) -> 顯示測試用 JSON 的 Mock 搜尋結果。
- 驗證「最近搜尋 (Recent Searches)」的 LocalStorage 存取流程與元件更新。
- 驗證找不到結果 (Empty State) 下的 UI 容錯回覆。
- 驗證「展開全文 / 收合」的操作。

### 階段三：自動化歸檔紀錄 (Logging)
- 完成測試且無發生 Hydration Error 手法確認後，建立當期開發記錄 `Phase14.10_AISearch_Bilingual.md`、更新 `CHANGELOG` 與 `DEV_SUMMARY`，並將此計畫歸檔至 `/doc/plans` 下。
