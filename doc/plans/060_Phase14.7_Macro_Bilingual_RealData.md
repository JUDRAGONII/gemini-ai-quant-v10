# 060_Phase14.7_Macro_Bilingual_RealData 計畫書

## 專案現況深度剖析 (Current State Analysis)

### 1. 前端頁面層級 (`app/macro`)
- **首頁 (`page.tsx`)**: 
  - **資料源**: 核心表格與指標已連接 `supabase.from('macro_indicators')` 的真實資料庫，但上方的 Quick Stats (`SmallStatCard`)（GDP、CPI、FED RATE）全為硬編碼假數據 (`2.9%`, `3.1%`)。
  - **語言層**: 主標題使用了 `<Bilingual>`，但諸如 `FAST SEARCH...`, `Deep Indicators Grid`, 按鈕名稱, Navbar 下的靜態徽章 (`DATA ENGINE`) 皆為寫死語言。
- **子明細頁 (`[indicator]/page.tsx`)**:
  - **資料源**: **100% 嚴重依賴硬編碼 MOCK**。完整依賴 `@/data/mockMacro.ts` 的 `findIndicatorByCode`。所有折線圖、最新數值全部都是靜態。
  - **語言層**: 所有頁面文字（包含 `最新數值`、`歷史走勢 (30 日)`、`更新頻率`）皆為硬編碼全中文，毫無雙語彈性。

### 2. 子元件層 (Components)
- **`EconomicCalendar.tsx`**: 已完美對接 `/api/v1/macro/calendar` 真實後端，但有諸多如「未來一週無重大經濟事件」、「實際」等字眼未雙語化。
- **`InsightsPanel.tsx`**: 分析面板部分中英混雜 (`跨資產關聯分析`、`Pearson Correlation`)，未完全支援 `<Bilingual>`。
- **`MacroIndicatorCard.tsx`**: 顯示標籤 `Last 24H` 為硬編碼。

### 3. 後端 API 與底層邏輯
- 後端已擁有 `backend/api/routers/macro.py` 與對應的 `macro_indicators` Supabase 資料表，資料欄位已透過 ETL 自動更新，這代表**我們不需要大改後端架構**，只需在前端拔除 Mock，切換至 Real Supabase Fetching 即可達成真實數據導入。

## 方案優化與 KISS 原則 (Trade-offs & KISS)
- **備選方案 A**: 在 Python Backend 重新設計 `/api/macro/:indicator` 端點來拋送數據。
- **推薦方案 B (KISS)**: 由於該模組主要以讀取為主，且前端環境已完善裝配 `supabase-js` 客戶端，直接使用 Next.js 客戶端的 `useSWR` 接 Supabase，可大幅節省中介層造成的延遲並保持一致渲染策略。我們將採用此設計。
