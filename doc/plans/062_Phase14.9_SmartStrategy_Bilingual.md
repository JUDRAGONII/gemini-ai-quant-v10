# Phase 14.9 智慧策略 (Smart Strategy) 雙語化與測試補齊計畫

智慧策略模組 (`app/ai/strategy`) 負責展現 AI 5D 先知模型的盤勢預測，以及啟動由後端 Python 進行的全向量化效能回測引擎。此模組為 V10.0 最具技術火力的分析核心。

## 專案現況深度剖析 (Current State Analysis)

### 1. 資料源與業務邏輯 (Backend / API Layer)
- **現狀極佳**：該模組透過 `useAIPrediction.ts` 與 `useBacktest.ts` 兩個 Hook 取得數據。
- 經過對照 `api/ai/backtest/run/route.ts` 與 `api/ai/predict/[symbol]/route.ts` 發現，所有請求已**直接透傳代理（Proxy）至外部 Python 架構的真實服務 (`AI_API_URL`)**。
- 不存在任何本地端的 Mock JSON 擋道，整體連線為 **100% 實戰就緒 (Real-Data Ready)**。

### 2. 前端介面靜態文字雙語化缺失
在 `page.tsx` 大多數文字與標題均已包裝為 `<Bilingual>`，但兩個關鍵數據可視化子元件未能套用：
- **`AIPredictionIndicator.tsx`**:
  - `AI 預測核心 (5D Alpha)`
  - `標的前景: {isPositive ? '看多 (Bullish)' : '偏弱 (Bearish)'}`
- **`StrategyMetricsGrid.tsx`**:
  - 包含 `總報酬率`, `年化回報 (CAGR)`, `最大回撤 (MDD)`, `夏普比率 (Sharpe)`, `索提諾比率`, `策略勝率`，這些都是透過硬編碼中文做為 `label` 傳入。

### 3. TDD 單元保險網狀況
- **嚴重缺失**：目前針對 `app/ai/strategy/page.tsx` 及其特有的組件，**完全沒有任何 Jest 測試檔案**，也就是對該頁面的自動化驗證覆蓋率為 0%。這會是日後重構與改版的龐大隱患。

## 預期改動與實作計畫 (Implementation Plan)

遵循 KISS 原則與先前的開發慣例，專注重點防禦網搭建與最後一哩的雙語視覺補齊。

### 階段一：精細化 UI 雙語補全 (Bilingual Enhancement)
#### [MODIFY] `components/AI/AIPredictionIndicator.tsx`
- 將表頭與 Gauge 針腳文字利用 `<Bilingual>` 或傳入雙語 prop 之形式封裝，無縫銜接英文語感。

#### [MODIFY] `components/AI/StrategyMetricsGrid.tsx`
- 將其子元件 `MetricCard` 的 `label` 型別定義由 `string` 更改為 `React.ReactNode`，允許在 `page` 內直接呼叫 `<Bilingual zh="..." en="..." />` 傳入。

### 階段二：TDD 單元測試保險防護 (Test Coverage)
#### [NEW] `__tests__/components/AI/AIPredictionIndicator.test.tsx`
- 模擬模型看多（Alpha > 0）、看空（Alpha < 0）以及 Loading Spinner 轉圈。
#### [NEW] `__tests__/components/AI/StrategyMetricsGrid.test.tsx`
- 驗證所有數值的四捨五入（toFixed）與文字有無脫落報錯。
#### [NEW] `__tests__/app/ai/strategy/page.test.tsx`
- 模擬 `useBacktest` 與 `useAIPrediction` 核心回傳，渲染頁面骨架並確保 `Sidebar`、`SearchBar` 順利 Render。

### 階段三：自動化歸檔紀錄 (Logging)
- 完成後，依照開發自動化歷程工作流 `0-0` 的精神，建立當期開發記錄、更新 `CHANGELOG` 與 `DEV_SUMMARY`，並歸檔此實作計畫至 `/doc/plans` 下。
