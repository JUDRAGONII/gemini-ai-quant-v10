你是一位經驗豐富的 QA 自動化測試專家。請嚴格執行以下程序，確保測試代碼具備高健壯性與安全性。

# 執行階段與里程碑

### STEP 1: 環境整備
- 檢查專案根目錄是否建立 `doc/test` 資料夾。
- 若無：請建立該資料夾。
- 若有：掃描現有 `.md` 檔案，避免重複命名。

### STEP 2: 撰寫測試案例清單 (發想階段)
- **來源**：參考 `.agent/workflows/test/template_02.md` 的結構。
- **格式規範**：
  1. 必須包含「測試目標」與「測試環境」。
  2. 案例必須使用 **TC-XXXX** 編號（1XXX: 基礎, 2XXX: 邊界, 3XXX: 安全, 4XXX: UX）。
  3. 維度：必須涵蓋「基礎路徑」、「邊界條件」及「Supabase RLS 安全性驗證」。
- **輸出**：在 `doc/test` 下生成一個 Markdown 檔案（建議格式：`YYYYMMDD_XX_功能名稱.md`）。
- **注意**：完成後請停下來，使用 `notify_user` 請求使用者確認 Markdown 內容。**禁止直接寫代碼。**

### STEP 3: 撰寫測試程式 (實作階段)
- **架構**：嚴格遵循 Next.js 14 測試規範，不同頁面/元件必須建立獨立測試檔案（如 `*.test.tsx` 或 `*.spec.ts`）。
- **目錄**：放置於 `frontend/__tests__/` 對應目錄下。
- **結構規則**：
  1. 第一層 `describe("頁面/功能名稱", ...)`
  2. 第二層 `describe("測試類型", ...)`：例如 `describe("安全性驗證", ...)` 或 `describe("UI 交互", ...)`。
  3. 第三層 `it("TC-XXXX: 測試說明", ...)`：**重要！** `it()` 內的編號與文字描述必須與 STEP 2 Markdown 中的原文 **完全一致**。
- **技術棧**：使用 `createServerClient` 或 `createBrowserClient` 進行測試中的 Supabase 調用。

### STEP 4: 執行驗證與同步
- 執行測試指令：`npm run test`。
- **同步狀態**：若測試 Pass，請自動將 `doc/test/*.md` 中對應的案例方框打勾 `[x]`。

### STEP 5: 異常回歸 (Max 5 嘗試)
- 若測試失敗，請分析報錯。
- 重複 STEP 3–4 修正代碼，上限 5 次。
