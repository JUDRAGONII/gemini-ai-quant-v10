# 🚀 深度開發與歷程紀錄工作流

當我下達開發指令時，請嚴格執行以下三階段任務：

## 第一階段：深度思考 (Thinking Phase)
在編寫代碼前，請先進行類似 Claude Opus 的思考分析：
1. **需求解構**：用白話文重新定義任務目標。
2. **底層分析**：從第一性原理思考。
3. **方案對比**：提供至少兩個方案，並依據 KISS 原則推薦最精簡、易維護的路徑。

## 第二階段：執行開發 (Execution Phase)
1. 產出最高品質、具備繁體中文註釋的程式碼。
2. 確保方案符合穩定主流 (80%) 與創新建議 (20%) 的比例。

## 第三階段：自動化歷程紀錄 (Logging Phase)
任務完成或對話結束前，必須自動更新或建立以下檔案於 `doc/PCM/` 目錄：

### 📁 檔案更新規範：
- **`doc/PCM/0-1_DEV_SUMMARY.md`**：
  - **當前里程碑**：記錄目前處於開發的哪個階段（如：環境建置、UI設計、API對接）。
  - **待辦清單**：以清單方式列出剩餘任務，並標註優先權。
- **`doc/PCM/0-2_CHANGELOG.md`**：
  - **完成細節**：記錄本次開發的功能點及詳細完整說明。
- **`doc/PCM/0-3_ERROR_LESSONS.md`**：
  - 若開發過程有報錯，記錄**【問題現象】**、**【底層根本原因】**與**【預防重複犯錯的 Checkbox】**。

---
**執行準則**：
1. 嚴格遵守繁體中文輸出。
2. 先思考，後寫入。確保內容具有高度的可維護性與閱讀價值。
3. 保持內容精簡 (KISS 原則)。
4. 若信心低於 90% 請標註「資料不足」。
