# 051_Phase8_Local_CI_Workflow.md

## 任務背景
由於 Phase 7.7 (型別錯誤) 與 Phase 7.8 (Jest 測試失敗) 連續導致 GitHub CI 崩潰，專案急需一套地端預檢機制。

## 本地 CI 工作流設計 (/local-ci-v10)

### 1. 核心檢查清單
- **前端型別檢查**：`tsc --noEmit`，捕捉任何型別偏移。
- **前端單元測試**：`jest`，驗證 UI 邏輯與文本一致性。
- **後端單元測試**：`pytest`，確保業務邏輯穩定。

### 2. 快連邏輯 (Chaining)
成功通過上述檢查後，工作流將自動引導至 `/git_push_v10`，實現一鍵驗證並推送。

## 執行效益
- **減少 CI 報錯**：將錯誤阻斷在地端。
- **節省部署時間**：避免頻繁修復小錯誤導致的建置排隊。
- **提升代碼認同度**：確保每一次推送都是「綠燈狀態」。
